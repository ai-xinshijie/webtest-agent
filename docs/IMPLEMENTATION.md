# WebTestAgent 实现与验收说明

## 交付范围

项目采用 TypeScript、Playwright、SQLite（`node:sqlite`）、Fastify、React 和 pnpm monorepo。没有引入 LangChain、Docker 或 `better-sqlite3`。

CLI、GUI 与核心 Agent 共用 `Orchestrator`：GUI 是管理层，不复制业务逻辑。`wta run` 默认提交任务给常驻 GUI/API 进程，`--foreground` 用于直接调试。会话、日志、测试结果、问题、覆盖快照和记忆都持久化到 `.wta/wta.db`。

## 感知与执行

主感知通道是 `StructuredPerceiver` 在浏览器上下文执行的精简提取脚本。它获取测试必要的 DOM、CSS 可见性、禁用状态、ARIA、可点击性信号、表单约束、坐标和稳定选择器；这比传入完整 HTML 更小、更稳定，也比单一无障碍快照拥有更多可执行信息。截图只在关键节点、错误证据和视觉分析需要时采集。

`cursor:pointer` 是可点击性信号之一，不是唯一判据。语义标签、ARIA role、`onclick`、`tabindex` 与 CSS 信号会共同评分。已发现但不可见或禁用的组件先执行 `scrollIntoViewIfNeeded`、可见性和启用态检查；点击类动作还会使用 Playwright 的 `trial click` 确认真实用户是否可达。系统绝不使用 `force: true` 绕过不可达状态。无法恢复的项目分为暂时受阻与永久受阻，并保留在报告中。

## 覆盖保证

1. BFS 探索同源可达页面并保存导航图，延迟补写尚未发现目标的导航边。
2. 动作覆盖为每个已识别组件类型生成可执行动作；成功、失败、复用、暂时受阻和永久受阻均有结果记录。业务组件计入主覆盖率，导航、页面外壳和第三方组件保留为探索证据并单独统计。
3. 小组合空间执行全笛卡尔组合；超出阈值时执行限定强度的 t-way 覆盖数组。
4. 路径覆盖对导航图枚举无循环的有限长度路径。
5. 每次动作记录前后页面状态节点和迁移证据；确定性语义 Oracle 检查页面稳定性、无效提交不可绕过校验、有效提交必须有可观察反馈。
6. 深度模式执行 HTTP 500、慢响应、离线三类网络故障注入。

系统不会宣称无限状态空间已被完全穷尽。每个报告分别给出动作、组合和路径覆盖分子分母，并记录受阻或待覆盖部分。实际覆盖率仅统计本会话真正执行的项目；已解析率包含页面指纹一致时复用的历史成功结果及已确认受阻项。空集合显示为 0%，不等同于已覆盖。状态图显示已发现状态与本会话通过/失败迁移，作为覆盖边界的审计证据。

## 重跑与记忆

`continue` 读取目标已测项，`fresh` 清空目标记忆，`retest` 只清空已测动作，`expand` 在可证明未变更的页面上优先已有经验并拓展组合，`regression` 重测失败项。只有当前页面指纹与历史指纹一致时，`continue` 和 `expand` 才允许复用历史成功动作；路径测试始终重新执行，避免将页面可打开误报为完整路径仍有效。会话完成时将轨迹压缩为结构化摘要；组件模式、质量规则和已测项可以导入、导出、合并和跨会话继承。

探索阶段会将持久化的页面和组件编译为可审阅用例：每个组件动作都有中文导航、动作、断言三步，包含稳定 selector、预期、导航宏和执行计数。类型未知或新增的组件会采用与测试引擎一致的通用点击动作，避免探索结果缺少步骤。仅执行 `--phase explore` 时会生成这些资产但不执行组件动作；`test` 阶段和完整流程会执行用例并回写通过、失败或跳过状态。`wta case list [--target <name>]`、`wta case show <caseId>` 用于查看资产，`wta case run <caseId> [--headed]` 以 `retest + test` 精确重跑一个用例，不会扩展到组合和混沌测试，也不会清理该目标其他动作的历史经验。

GUI 的“用例”页提供同样的步骤、断言、最近状态与单条运行操作。报告页可直接读取并预览 Markdown/JSON；两种报告均包含编译用例、步骤、断言、最近状态和执行时间，故探索会话也可审阅测试计划。

## 模型、规则与自进化

模型路由按任务类别独立配置，例如组件识别、探索决策、质量推理、视觉分析、记忆压缩与代码修复。文本和视觉模型可使用不同提供方。

通用“公理”由内置质量规则、可信组件签名和置信度约束承担；目标“本体”由当前系统的页面、组件、交互、约束和导航图承担。模型不能直接把猜测写为全局规则，只有带证据、置信度和验证记录的模式才可继承。

## 常驻与自愈

常驻进程通过 `/api/run` 维护会话，CLI 可使用 `status`、`attach`、`stop`，GUI 用 WebSocket 推送会话摘要并以时间线展示详细日志。浏览器崩溃最多自动重启两次。

代码级自愈默认 `review`：模型可输出诊断和最小文本补丁建议，但不自动修改源码。`auto` 模式仍限制补丁路径、长度、唯一定位和高风险 API，随后运行构建与非覆盖率测试；任何失败均回滚。失败会话也会生成双格式报告并包含热修复诊断。

## 浏览器与 Linux

浏览器二进制随仓库 `vendor/browsers` 使用 Git LFS 分发。`BrowserManager` 按当前操作系统筛选可执行文件，Windows 不选 Linux 二进制，Linux 不选 `.exe`。Linux 无头环境需要先执行 `wta install deps` 安装系统库；不要求 Docker，也不使用用户已安装浏览器。

## 测试策略

单元和集成测试覆盖核心、CLI、GUI API 和 React GUI。测试文案、日志、报告和代码注释均为中文。严格验证使用：

```bash
pnpm build
pnpm test
```

测试门禁要求语句、分支、函数和行覆盖率均为 100%，且不会通过降低阈值或排除实现源码绕过。
